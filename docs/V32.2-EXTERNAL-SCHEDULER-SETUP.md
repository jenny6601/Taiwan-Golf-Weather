# V32.2 External Scheduler Backup

Purpose: provide a second trigger for the isolated V32.2 live-data publisher when GitHub's native scheduled event is delayed or missed.

## Safety boundary

- Target workflow: `.github/workflows/v32-observation-collector.yml`
- Target ref: `main`
- Dispatch event only; the workflow checks out the V32.2 feature branch for collection.
- The publisher writes only `data/live_observations.json` and `v32.2-preview.html` to `main`.
- Do not merge PR #4, change `index.html`, or replace the V31.6 homepage as part of scheduler setup.

## 1. Create a narrowly scoped GitHub token

In GitHub, open Settings -> Developer settings -> Personal access tokens -> Fine-grained tokens.

Create a token with:
- Resource owner: the owner of `jenny6601/Taiwan-Golf-Weather`
- Repository access: only `Taiwan-Golf-Weather`
- Repository permissions: Actions = Read and write
- No Contents, Administration, or other permissions
- Set an expiration and rotate it periodically

Copy the token once. Do not put it in source code, HTML, a URL, or a chat message.

## 2. Configure cron-job.org

Create an account at https://cron-job.org/ and add a cron job:

- Title: `Taiwan Golf Weather V32.2 backup trigger`
- URL: `https://api.github.com/repos/jenny6601/Taiwan-Golf-Weather/actions/workflows/v32-observation-collector.yml/dispatches`
- Method: POST
- Schedule: every 10 minutes
- Time zone: Asia/Taipei
- Request timeout: 60 seconds (or the closest available setting)
- Save responses: enabled during initial testing

Add these custom HTTP headers:

```
Accept: application/vnd.github+json
Authorization: Bearer <YOUR_FINE_GRAINED_GITHUB_TOKEN>
X-GitHub-Api-Version: 2022-11-28
Content-Type: application/json
```

Request body:

```json
{"ref":"main"}
```

A successful GitHub workflow-dispatch request normally returns HTTP 204 (no response body).

## 3. Verify before relying on it

1. Use cron-job.org's manual test/run function once.
2. Confirm a new run appears in GitHub Actions with workflow name `V32.2 Scheduled Live Data Publisher`, event `workflow_dispatch`, and branch `main`.
3. Confirm the run succeeds.
4. Confirm `data/live_observations.json` has a newer `generated_at` timestamp and still contains 57 courses.
5. Wait for at least two scheduled intervals and confirm the external job history and GitHub Actions each show successful triggers.

## Important limitations

- This is a backup trigger, not a guarantee of uninterrupted service. cron-job.org notes that execution can be delayed and does not guarantee exact punctuality.
- Keep GitHub's native schedule enabled as a second independent trigger.
- The workflow's concurrency group prevents overlapping publisher runs.
- If either service fails, inspect its execution history and the GitHub Actions run logs.
- Never share the token in chat or commit it to the repository. If exposed, revoke it immediately and create a replacement.
